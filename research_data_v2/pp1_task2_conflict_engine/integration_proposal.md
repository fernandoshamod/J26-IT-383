# Proposed safe integration into dynamic recommendations — not implemented

1. **Approve evidence schema and data owner.** Use the Task 1 [vendor_pair_evidence](../audit_2026-10-17_01/schemas/vendor_pair_evidence.csv), [vendor_resource_requirements](../audit_2026-10-17_01/schemas/vendor_resource_requirements.csv), and [data_provenance](../audit_2026-10-17_01/schemas/data_provenance.csv) templates as starting points. Require immutable source IDs, evidence class, scope, timestamp, license/permission and reviewer. Event-specific evidence must match the current USER event. Do not load historical SIMEVT collaboration rows as current evidence.
2. **Resolve source option IDs, then evaluate.** The existing [dynamic service](../../backend/engine/dynamic_package_service.py) creates fresh combinations from current options. After canonical option selection and before final ranking, an adapter could pass vendor IDs, service intervals and documented resource requirements to this engine. It must not replace dynamic generation or load a package catalog.
3. **Map statuses conservatively.** An evidence-backed conflict may add a FAIL check. Unknown, contradictory, stale or incomplete evidence adds VERIFICATION_REQUIRED. A scoped compatible result only passes that specific pair/operational check; it never changes venue or booking availability to pass. Keep category compatibility as a separate static heuristic, not a proxy for named-vendor cooperation.
4. **Keep research controls.** Feature flag the adapter, preserve existing production ranking weights and APIs, compare before/after outputs on identical generated package pools, and record false-warning/pending rates. Validate every examined package before ranking, without expanding the existing search cap. Review fixture-to-real data mapping before activation.
5. **Venue boundary.** Send requirements and provenance to the external Venue Suitability / Digital Twin component under the Task 1 [contract](../audit_2026-10-17_01/venue_integration_contract.md). Do not implement venue rules here.

**Integration gate:** real vendor pair/availability data and shared resource constraints are currently unavailable. Production integration should stay pending until evidence ownership, schema validation, trusted import, tests and rollback criteria are agreed.
