# Dataset V2 schema proposal

**Status:** proposal only; no V2 data created. Use immutable `dataset_version`, `source_snapshot_id`, `transform_version`, `evidence_class` (REAL_PUBLIC, DERIVED, SYNTHETIC_TEST, UNKNOWN), `source_record_id`, `source_file_sha256`, `observed_at`, `verified_at`, and `verification_status` on every evidence-bearing row or through a field-level provenance table. Preserve source IDs and distinguish simulated assertions from real evidence. A null value plus `UNKNOWN` is valid and must not be filled with plausible numbers.

| Table / key fields | Source and provenance | Validation | Unknown until external evidence |
|---|---|---|---|
| `source_snapshots(snapshot_id, dataset_name, path, sha256, acquired_at, license_ref, transform_version)` | Original local Yelp files plus documented acquisition metadata; hash REAL_PUBLIC source bytes, metadata otherwise UNKNOWN if absent | Unique hash/path/version; immutable records; verify agreement reference | Download authorization, acquisition date, current rights if undocumented |
| `vendors(vendor_id, source_business_id, name, categories_raw, city, state, lat, lon, stars, review_count, is_open_at_snapshot)` | Yelp business rows REAL_PUBLIC; service classification in separate fields DERIVED | Unique source ID, FK snapshot, coordinate/rating ranges; retain original value and any CSV-rounded value | Present operation, offered event service, service radius, vendor consent |
| `reviews(review_id, vendor_id, review_date, stars, text_ref, source_snapshot_id)` | Yelp review JSONL REAL_PUBLIC, preferably controlled-access IDs/features rather than redistributing text | Unique review ID, FK vendor when selected, valid dates/stars; stream ingestion; permitted-use review | Review authenticity beyond source and operational failure causality |
| `review_features(vendor_id, count, mean_stars, sample_std, latest_date, window, formula_version)` | DERIVED from review rows | Recompute deterministically; record denominator and sample/population std; compare to source review_count without equating them | Failure risk or service reliability label |
| `vendor_service_classifications(vendor_id, category, rule_id, matched_source_terms, confidence, review_status)` | DERIVED from raw business categories/attributes, rule version | Allowed category vocabulary, inspect ambiguous mappings, one row per vendor/category/rule | Actual ability to deliver the service |
| `service_options(option_id, vendor_id, category, tier, supported_event_types, service_area_id, offer_status)` | Existing V1 fields SYNTHETIC_TEST; future confirmed documents/quotes could be separately REAL_PUBLIC or private verified evidence | Unique option ID, FK vendor, controlled category/event values, evidence status per field | Actual tier, inclusions, event-type acceptance, travel radius |
| `capacity_rules(option_id, min_guests, max_guests, basis, source_doc_id, valid_from, valid_to)` | V1 random Catering caps SYNTHETIC_TEST, future vendor/venue confirmation required | min≤max, guest units, date validity, category applicability, explicit unknown for non-Catering | Real maximum guests, staffing/throughput, venue capacity |
| `pricing_rules(option_id, currency, amount, billing_basis, minimum_units, taxes, travel_fee_rule, quote_date, expires_at)` | V1 illustrative USD values SYNTHETIC_TEST; future dated quotations as verified evidence | Positive amount, supported basis, currency, validity, inclusive/exclusive fee flags, exchange-rate source/version | Actual quotation, total bill, travel/tax amount |
| `operational_resources(resource_id, vendor_id, type, quantity, exclusive, time_window)` and `option_resource_needs(option_id, resource_id/type, quantity, setup/teardown)` | Controlled simulation fixtures SYNTHETIC_TEST; vendor inventory confirmation later | Nonnegative quantities, interval overlap rules, FK and source evidence | Real shared crew, equipment, setup/teardown limits |
| `availability_evidence(availability_id, vendor_id, event_id, start_at, end_at, status, source_doc_id)` | SIMEVT random values SYNTHETIC_TEST; genuine calendars/confirmations later | Timezone-aware half-open intervals, event-specific FK, source and checked_at, contradictions remain unresolved | New USER-event availability until checked |
| `category_compatibility_rules(category_a, category_b, score, rationale, rule_version)` | Current 15-row matrix DERIVED heuristic | Canonical sorted pair, unique pair, score 0–100, missing pairs explicitly unknown | Real vendor-pair cooperation |
| `vendor_pair_evidence(pair_id, vendor_a_id, vendor_b_id, event_id, observed_outcome, source_doc_id, adjudicator, confidence)` | Existing random pairs SYNTHETIC_TEST only; verified joint-event evidence in future | Canonical pair, distinct IDs, event/time and source required for verified status, no synthetic label promoted | Actual collaboration/conflict, failure outcome |
| `event_requirements(event_id, event_type, city, state, guests, start/end, budget, currency, required_services, venue_id, evidence_class)` | 30 V1 templates SYNTHETIC_TEST; USER request values as submitted requirements, not vendor facts | Positive guests/budget, duration, controlled services, fixed exchange assumptions | Venue suitability and real booking status |
| `evaluation_scenarios(scenario_id, frozen_inputs, cohort, split, source_version)` and `evaluation_labels(scenario_id, label, evidence_doc, adjudicator, observed_at)` | Independently authored synthetic fixtures SYNTHETIC_TEST; real outcomes only with documented observation | Freeze before model comparison; pair/vendor/time disjoint splits; separate synthetic oracle from real labels; no circular labels | Real-world success/failure until independent evidence exists |

Field-level provenance must be queryable. A table-level flag alone is insufficient when a row mixes Yelp identity with generated prices. Define `field_evidence(entity, entity_id, field_name, evidence_class, source_snapshot_id, source_record_id, transform_version, verification_status, reason)`; require it for any non-null operational value. Never infer a real quote from Yelp's ordinal restaurant price marker. Preserve V1 as a frozen baseline and give V2 new IDs/namespace so no overwrite occurs.
