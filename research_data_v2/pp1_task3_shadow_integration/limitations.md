# Evidence and scope limitations

1. Current option rows contain vendor/option IDs, service category, simulated event/location support, price/capacity assumptions and a setup-minute field. They do not contain option-specific service intervals, timezone, teardown duration, event-specific availability, shared equipment ownership, crew assignments, resource quantities or limits. Task 2's full `evaluate_case` requires timezone-aware service intervals. Mapping the overall event interval onto every option would invent a schedule, so the operational evaluator is not run.
2. The current source has no independently verified vendor-pair observations for new USER events. Task 2 synthetic fixtures are excluded. Every tested pair is unknown; absence of a recorded conflict is not proof of compatibility.
3. `setup_space_m2` and `power_kw` are simulated venue requirements, not documented vendor-owned resource capacities. Venue suitability remains the other group member's component and is marked external.
4. Current service options and prices are synthetic simulation data. Risk labels and category compatibility in the original package are rule-derived or category-level, not verified vendor collaboration or real-world failure predictions. The shadow assessment neither changes nor endorses those scores.
5. Only returned top-K packages were shadow assessed. The production generator validates all examined complete combinations before its own selection, but this prototype does not shadow-assess discarded combinations. Candidate truncation limits generalization to all possible options.
6. Timing is from one local virtual-environment run, not deployed latency. The measured adapter time excludes source CSV load and production generation time.
7. No verified evidence was supplied, so conflict detection sensitivity and false-positive rate cannot be estimated from this shadow run. Task 2's controlled fixture metrics remain SYNTHETIC_TEST and are not real-world accuracy.
8. The adapter checks source IDs, category, event type and simulated location. It does not independently re-price or revalidate capacity; those remain the production feasibility engine's responsibility in this read-only prototype.
