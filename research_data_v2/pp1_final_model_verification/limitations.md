# Evidence and claim limitations

- **Target is rule-derived.** Low/Medium/High comes from mean review rating, rating standard deviation, and collected review count. All three rule inputs are among the five model features. The 18,430 stored labels match the deterministic rule exactly. A 100% reconstructed holdout score shows rule imitation, not prediction of observed service failure, cancellations, contractual risk, or reliability.
- **Holdout reconstruction has a provenance boundary.** The [notebook](../../notebooks/01_vendor_dataset_audit.ipynb) records the split recipe and the ordered source file is unchanged on the audited fields, but original held-out row IDs and a signed training-run manifest were not persisted. Exact artifact training membership is **NOT_VERIFIED** beyond notebook code and metadata.
- **No independent outcome labels.** Real-world vendor failures, booking outcomes, actual compatibility, availability, and quotation accuracy are **NOT_VERIFIED**. Do not advertise 100% real-world risk accuracy. The model probabilities are classifier scores over rule labels, not calibrated operational failure probabilities.
- **Production ranking nuance.** Package ranking uses the rule-derived numeric favorability score when available; model prediction gates its availability on agreement. It does not rank directly on the Low/Medium/High label. The live API can generate packages only where the separate synthetic option data and search rules permit it.
- **Frontend paths differ.** Vendor and package views display classes from a current API response. The AI Model dashboard displays saved evaluation JSON. Its presence is not evidence of a new model execution. Browser screenshots reflect the existing compiled build and one local audit session, not deployment or all device sizes.
- **Input/service quality.** Some source category assignments appear broad in the rendered vendor table and need manual review before PP1. A technically correct risk class does not establish that a vendor offers the selected event service.
- **Feature importance.** The chart reports impurity importance from the saved forest. It does not establish causal effects or generalization to future vendors.
- **UI and server scope.** A local FastAPI TestClient route and existing compiled frontend were exercised. Public deployment, remote reachability, traffic performance, and durable user state were **NOT_VERIFIED**. The temporary audit-only proxy was stopped after screenshot capture.
- **No changes to production.** [source_hashes.csv](./source_hashes.csv) shows matching before/after SHA-256 for 15 inventoried artifact, data, notebook, backend, and frontend inputs. This is not a whole-drive snapshot.
